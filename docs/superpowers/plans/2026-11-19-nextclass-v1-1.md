## Global Constraints

- Preserve existing data, working features, architecture and application identity.
- Maintain NextClass's bold, high-contrast Neo-Brutalist design.
- Preserve timetable scans at 2 per day and 3 per rolling 7-day window; do not apply those limits to exam scans.
- Only persist imported examinations after explicit student confirmation.
- Regular university classes stop throughout the confirmed active examination period.
- Compare exam-mode dates in the device's local timezone.
- Do not reset the database or destroy existing classes, quizzes, settings, or scan history.
- Do not add a backend or authentication system.
- Do not claim that AI-powered scanning happens entirely offline.

## Review Focus

- Local-midnight boundaries and app resume while an exam period is active → mode and notification tests.
- Active schedule empty/deleted and only-past exam dates → repository/mode tests.
- Imported Excel dates as serial values, merged cells, empty files, and unsupported `.xls` → parser tests.
- Timetable replacement and class deletion while quizzes exist → migration/repository regression tests.
- Notification settings denied/changed during Exam Mode → scheduling tests.

## Tasks

### Task 1 — Exam entities, settings, and migration

Add exam schedule/exam models, a repository with active schedule selection and CRUD, exam reminder fields with defaults, and a versioned migration that leaves current tables/data intact. Write migration and repository tests first.

### Task 2 — Central academic schedule mode

Add one date-normalizing service that computes start/end from the active schedule and answers whether a supplied local calendar date is in Exam Mode. Cover pre-period, endpoints, gaps, single-day periods, empty/past schedules, and schedule edits/deletes.

### Task 3 — Exam sheet import and review

Add document picking and supported-format validation. Send PDF/image bytes to Gemini; parse `.xlsx` cells locally (including merged-cell propagation and date normalization), then use Gemini only when the normalized rows need interpretation. Ask program, semester, and section separately, flag uncertain matches, and require review/explicit save. Manually add/edit/delete exams and display saved exams offline. Reject malformed files and `.xls` when unsupported.

### Task 4 — Effective schedule in app navigation and screens

Use the shared mode service in Today and Week so the active exam period replaces class entries even on exam-free dates. Add an Exam Mode badge/empty state and exam browsing/navigation. Add the center orange accessible plus action to the existing bar, with Add Quiz and Add Exam actions and no duplicate navigation stack. Remove the oversized home quiz prompt.

### Task 5 — Notification reconciliation

Add independent exam reminder settings and stable identifiers. Reconcile upcoming exam reminders and cancel conflicting weekly class reminders for every date in the active exam range; keep quiz reminders independent. Reconcile on startup/resume and after schedule/settings mutations. Test deduplication, suppression, restoration, edits, and non-past scheduling.

### Task 6 — Quiz occurrence time

Remove quiz-specific time and end-date inputs. When a class is chosen, derive the recurring weekday occurrence from the picked date and store its date/time association without dropping existing quiz rows. Preserve quizzes through timetable replacement and use occurrence time for related reminder calculations. Add regression tests.

### Task 7 — Privacy and marketing copy

Update in-app, standalone, and marketing disclosures to say that a selected timetable/exam document is sent to Google's Gemini service for AI extraction when scanning is used; confirmed schedule records remain stored locally. Preserve page design.

### Task 8 — Integration verification

Format changed Dart files; run targeted tests, static analysis, then the Flutter test suite if the Flutter SDK is available. Fix integration regressions and report any blocked checks precisely.
